# 40枚全駒煙の飾り駒調べ（2026-10-12）

初形の各駒について、盤から取り除いて受方の持駒に移しても最短解が一意で、元と同じ手順のままなら
「飾り駒」と判定した（論文の「狼煙」3七香と同じ基準）。成駒は元の駒として受方持駒に入れる。

## 結果

| 集合 | 手数 | 局数 | 飾り駒なし | 飾り駒1枚 |
|---|---|---|---|---|
| 「狼煙」発表図 | 113 | 1 | 0 | 1（3七香） |
| 2618候補（`paper/main/verification/sources/40piece_solutions.txt`） | 113 | 2618 | **42** | 2576（1五香 1938、3七香 638） |
| d=34 起点 run の115手（`scratch/40piece_salvage/40piece_115ply.sfen`） | 115 | 67 | **67** | 0 |
| 同 run の代表局（109手・113手） | 109/113 | 2 | 0 | 2（1八と、1五香） |
| 幅を小さくした d=34 起点 run（`rust/analysis/smoke_cone/data_v2/best_step_113.txt`） | 113 | 1084 | **54** | 1030（3七香 868、1五香 162） |

- どの集合でも、元の局面の最短解は fmrs で一意（`set_*.out.jsonl` の `unique`）。
- 2局（2618候補の飾り駒なし42局の先頭と、115手67局の先頭）は、python-shogi 1.1.1 による
  別実装の幅優先探索（`scratch/tofu_smoke/verify_bfs.py`）でも確かめた。元の局面は最短解が一意で、
  38枚のどれを取り除いても最短解が変わる（より短い詰みが生じるか、別の解になる）
  （`indep_*_inputs.txt` が入力、`indep_*.jsonl` が結果）。

## 再現

```sh
python3 kazari.py <fmrs バイナリ> out.jsonl <SFEN または URL の一覧> [並列数]
```

fmrs は 720d99c 以降のビルド（`solve standard` を使う。1局あたり 0.02 秒程度）。
